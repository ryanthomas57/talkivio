Talkivio Claude Code Master Prompt
Complete production implementation specification
Build a working multi tenant live chat platform with the functional breadth of classic Zendesk Chat and Zopim from the 2019 to 2021 era, expressed through an original Talkivio identity. This document is the prompt: copy its full text into Claude Code, or give Claude Code access to an extracted text version and instruct it to execute all requirements.
The deliverable is deployable end to end software. Every customer facing action must persist, authorize, validate, report errors, and work across real browsers and independent sessions. Screenshots, static prototypes, hardcoded analytics, local only chat simulators, and decorative controls do not satisfy this specification.
Core scope is mandatory. Billing, custom domains, advanced white label branding, SAML, and optional provider adapters are explicitly identified extensions. Optional features must never conceal unfinished core capabilities. Implement core first and retain clear feature boundaries.
Use the numbered requirements, API and event contracts, data definitions, test fixtures, and audit checklist as the implementation authority. Preserve this file as the replacement master prompt. Do not depend on the earlier Word document.

01  Execution mandate and completion standard
Instruction to Claude Code
You are the lead engineer, product designer, security engineer, and release owner for Talkivio. Inspect the repository, applicable instructions, runtime constraints, and existing implementation before modifying anything. Then implement this complete specification. Make routine decisions autonomously, record architectural decisions, and continue until all mandatory acceptance criteria have evidence. Ask only for genuinely unavailable credentials, mutually incompatible requirements, or authorization for a destructive external action. Lack of a commercial credential is not a reason to stop local end to end delivery: supply a real local mail server, object store, scanner, and webhook receiver.
Non negotiable output
Deliver source code, migrations, generated OpenAPI and AsyncAPI contracts, reproducible seed data, unit and integration tests, browser tests, Docker images and Compose environment, CI pipelines, operational runbooks, backups and recovery procedures, threat model, accessibility evidence, and a requirements traceability ledger. Every advertised feature must have a functional implementation or an explicit optional disabled state. No TODO driven handlers, simulated successful requests, fake socket deliveries, seeded values masquerading as live analytics, or unconnected UI controls.
Completion evidence
For each requirement create an ID, implementation location, test name, latest test outcome, and evidence path in docs/traceability.csv. Distinguish implemented, verified, blocked, optional disabled, and failed. Never relabel failed or blocked work as complete. A release is ready only after two tenants, two agents, and visitors on two separate origins exchange messages through actual services, routing and triggers operate, exports download, erasure removes personal data, and a deployment smoke test passes.
Autonomous continuity
Write durable progress to docs/implementation-status.md after each phase. On context exhaustion or restart, reread this specification, architecture decisions, ledger, failing test output, and repository state. Resume the first unmet dependency. Do not restart completed phases or remove a requirement to make tests pass. Preserve useful work when a third party is unavailable and state the exact blocked adapter separately.
02  Scope and product boundaries
Mandatory classic chat scope
Implement agent dashboard, visitor monitoring, real time chats, manual and automatic assignment, broadcast routing, departments, availability and capacity, agent collaboration, transfers, notes, typing indicators, unread and delivery state, attachments, chat ratings, history and search, transcript export and email, canned replies, tags, bans, proactive invitations, deterministic triggers, operating hours, offline contact forms, embeddable widget, visitor tracking and identity, analytics, tenant administration, role permissions, integration webhooks, account security, retention, and audit logs.
Original visual identity
Use Talkivio naming and its own navigation, components, typography, iconography, copy, and palette. Functional scope is the benchmark; do not copy Zendesk logos, proprietary assets, marketing text, source code, or pixel identical screens. Do not import modern messaging or AI bot behavior into the classic live session model by accident. Closed live chats stay closed; a new visitor request creates a new chat linked to the same visitor identity.
Core and extension split
Core includes email password authentication, password reset, TOTP, REST integration tokens, inbound visitor API, outbound signed webhooks, and local SMTP. Optional modules: payment provider billing, SAML/OIDC enterprise identity, custom widget domains, full white label, CRM connectors, support ticket connectors, skills based routing, and external data warehouse export. Provide connector architecture and local contract tests even when paid adapters are disabled. Do not claim an adapter is operational without credentials and a tested provider round trip.
Explicit defaults
English is default; all copy is localizable. UTC is database time; account display timezone defaults to UTC until chosen. Default plan has 10 enabled agents, capacity 3 chats per agent, file limit 10 MiB, 180 day transcript retention, 30 day raw page event retention, and no proactive tracking before the configured consent condition. These are Talkivio product defaults, not claims about historical Zendesk settings. All thresholds are configuration with documented bounds.
03  Architecture and repository contract
Reference stack
Use a TypeScript monorepo: React with Vite for dashboard and widget UI; a small separately bundled loader; Node LTS with Fastify for REST and WebSocket gateway; PostgreSQL for durable truth; Redis for ephemeral presence, rate limits and work coordination; durable PostgreSQL outbox plus worker queues; S3 compatible object storage; SMTP mail provider; ClamAV attachment scanner. Pin supported versions and exact lockfiles at implementation time. Generate runtime validators from shared schemas. Alternative stack requires a recorded equivalent design and complete contract coverage.
Package responsibilities
apps/dashboard owns agent and administration surfaces. apps/widget owns isolated iframe UI. apps/api owns authentication, authorization and command transactions. apps/gateway owns authenticated transport and replay. apps/worker owns outbox, scans, analytics aggregation, email, exports and retention. packages/contracts owns schemas, enums and generated clients. packages/ui owns tokens and accessible primitives. packages/routing and packages/triggers contain pure deterministic decision logic. infra contains Compose, Dockerfiles, reverse proxy, CI and production examples. docs contains evidence and runbooks.
Transactions and delivery
A command transaction validates permissions and row versions, writes domain rows and an outbox event, then commits. A worker publishes committed outbox events. Delivery is at least once; client and consumer deduplication gives one observable result. Never send a socket success before persistence. Redis loss must not destroy messages, reservations, routing decisions, or trigger action uniqueness. Worker claims use durable leases and retry schedules. A gateway restart must support snapshot plus cursor recovery.
Boundary verification
Browser tests use HTTP and sockets against Compose, not bypass database fixtures for the main journey. A process kill after commit but before publish must replay the outbox. Split API and gateway replicas share no required in process state. Access the object store only through scoped upload and download grants. No browser bundle includes administrative, billing or signing secrets.
04  Tenant isolation and permission model
Tenant resolution
Every authenticated request resolves active tenant membership server side. Tenant IDs from request bodies are never authority. Widget bootstrap maps public site key plus validated origin to a tenant and site. Agent sockets bind tenant and membership at handshake; visitor sockets bind site, visitor and session. A principal cannot subscribe to arbitrary tenant, visitor, or chat IDs. Set transaction local database tenant context on every database operation and reset pooled connections safely.
Roles and scope
Owner manages ownership, billing, tenant destruction, secrets and all settings. Admin manages agents, departments, triggers, sites, retention and integrations but cannot transfer ownership or reveal payment secrets. Supervisor monitors assigned departments, views their history and analytics, transfers chats, and coaches agents. Agent serves eligible departments, sees assigned chats plus department queues, uses shared replies, and edits limited visitor metadata. Analyst views permitted aggregate analytics only; transcript access requires a separate permission. Custom roles are optional; explicit server permissions remain required.
Database defense
Use PostgreSQL RLS with both USING and WITH CHECK for tenant owned tables. Application role must not own tables or have BYPASSRLS; FORCE ROW LEVEL SECURITY where applicable. Use composite foreign keys including tenant_id so cross tenant references fail even if application validation is wrong. Public entry points use narrow dedicated operations, never a broad tenant bypass. Maintenance jobs select an explicit tenant scope and generate audited operations.
Acceptance criteria
Tenant A cannot read, write, search, export, attach to, subscribe to, or infer existence of tenant B objects. Test guessed UUIDs in paths, filters, socket subscriptions, upload IDs, batch APIs and signed downloads. Missing or unauthorized objects return the same 404 shape. Revocation of membership closes active sockets and invalidates sessions within 60 seconds. RLS tests run as the actual non owner application role.
05  Design tokens and component system
Visual tokens
Use Inter when licensed and bundled, with Arial and system sans fallbacks. Colors: canvas #F4F7FA, surface #FFFFFF, strong text #17222E, secondary text #4C5D70, subdued text #627286, border #D5DEE8, primary #176B73, primary hover #10515A, primary tint #E5F3F2, danger #B42318, danger tint #FFF0EE, warning #8A4B00, success #18734A. Test contrast on actual combinations. Do not use subdued colors for critical state labels. Use text and icons with color for every presence and severity state.
Layout and typography
Spacing scale 4, 8, 12, 16, 20, 24, 32, 40, 48 px. Base UI text 14 px with 20 px line height; secondary 12/16; body 16/24 for forms and widget; H1 28/36 weight 650; H2 20/28 weight 600; H3 16/24 weight 600. Dashboard panels use 24 px padding desktop and 16 px compact. Cards have 12 px radius, controls 8 px, pills 999 px. Border 1 px; focus ring 2 px #176B73 with 2 px offset. Shadow only for floating menus, dialogs and widget, never every row.
Control dimensions and states
Inputs and buttons default 40 px high; touch targets at least 44 by 44 px. Input padding 12 px horizontal and 10 px vertical. States: idle, hover, focused, filled, invalid, disabled, read only and submitting. Invalid inputs have icon, text below and aria-describedby. Disabled controls explain dependencies when useful. Primary action loading retains width and label context. Menus use 8 px inset and 36 px item minimum; keyboard arrows, Home, End, typeahead and Escape work. Tooltips appear after 500 ms and are never the sole label.
Reusable components
Build button, text input, password input, textarea, select, combobox, switch, checkbox, radio group, badge, avatar, tabs, data table, virtual list, drawer, dialog, toast, banner, calendar, timezone picker, empty state, skeleton, file tile, message bubble and connection indicator. Each has documented props, keyboard behavior, accessible name, error example and responsive story. Do not substitute custom clickable divs for native semantic controls.
06  Responsive shell and global interactions
Breakpoints and regions
Use mobile below 640 px; compact 640 to 1023; desktop 1024 to 1439; wide 1440 and above. Desktop sidebar 224 px, topbar 64 px, content gap 24 px. Compact sidebar collapses to 64 px icons with accessible labels. Mobile navigation becomes a modal drawer with 56 px topbar. Chat workspace on wide screens has 280 px queue, flexible conversation minimum 400 px, 320 px visitor panel. Below 1200 px visitor panel is a drawer; below 900 px queue and chat use separate routes with a back action. Never shrink the composer below usable width.
Navigation and persistence
Sidebar routes: Overview, Visitors, Inbox, History, Monitor, Analytics, Shortcuts, Team, Settings. Hide routes by permission while preserving direct route authorization. Browser back and forward restore filters, selected chat and scroll position. Persist table column preferences per membership, saved filters per tenant or personal scope, and drafts per chat per agent browser. Tenant switching closes old sockets, clears caches and drafts from visible context, and resubscribes only after fresh authorization.
Global states
Initial load uses skeletons shaped like the final layout. Partial errors stay in the failing panel with Retry. Empty lists explain the current filter and provide a meaningful action. A persistent connection banner shows connecting, live, reconnecting and offline. Toasts do not carry the sole evidence of failed writes. Confirmation dialogs state the object name and consequence; dangerous actions require explicit confirm, not browser alerts. Unsaved settings prompt on navigation, with Save, Discard and Cancel.
Acceptance criteria
At widths 320, 375, 768, 1024 and 1440 px and 200 percent zoom, controls remain operable and no page has unintended horizontal overflow. Modals trap focus and return focus to their opener. Escape dismisses overlays without deleting drafts. Routes load by direct URL and survive refresh. A session expiry prompts login and preserves unsent drafts securely without sending them automatically after reauthentication.
07  Authentication and account lifecycle
Required behavior
Support tenant signup, verification email, invite acceptance, login, logout, password reset, TOTP enrollment and recovery codes. Require verification before inviting other agents. Password minimum 12 characters and maximum 128; permit paste and password managers. Store Argon2id hashes, never reversible passwords. Reset and invitation tokens are random, hashed in storage, single use, and expire after 30 minutes and 7 days respectively. Account enumeration responses are generic. Revoke all sessions on password reset; require recent reauthentication for owner transfer and credential changes.
Interface and interaction
Login card max width 420 px with 24 px padding, email above password, explicit Show password and inline validation. Verify and reset success pages provide one clear next action. TOTP setup presents QR plus manual key, requires a valid code before activation, and displays recovery codes once with download and copy. Recovery uses single use codes. Session list includes browser, approximate location, last active time, and revoke action.
Implementation contract
Use HttpOnly Secure SameSite=Lax session cookies for dashboard, rotate session ID on login and privilege change, and require CSRF token on cookie authenticated mutations. Enforce rate limits by account hash and network. No bearer token in localStorage for dashboard. TOTP secrets are encrypted with key version. Save authentication audit events without passwords, OTPs or raw tokens.
Acceptance criteria
Given a used reset link, a second submission fails safely and does not log the user in. Given five bad attempts, rate limits apply without locking every user behind one shared IP. Given revoked membership, both REST and existing sockets reject operations. Login CSRF, reset token replay, MFA brute force and session fixation tests pass.
08  Onboarding sites and widget installation
Required behavior
Create tenant, choose display timezone, add first site and allowed origins, configure first department and install code. Site public key identifies a site but grants no administrative access. Origin entries are exact scheme plus host plus optional port; HTTPS required outside localhost. Wildcards are optional only as explicit subdomain patterns with public suffix protection. Publish settings as immutable versioned snapshots. Installation check confirms a real bootstrap event from an allowed origin and displays last verified time.
Interface and interaction
A five step onboarding flow has progress, Back and resumable saved state. Installation panel shows copyable loader snippet, allowed domain list, preview, installation test, and checklist. Preview uses isolated test mode with a visible Preview label and cannot pollute production analytics. Empty department picker links to create a department if permitted. Invalid origin text identifies the exact field.
Implementation contract
Persist sites and widget configuration revisions; use If-Match revision checks. Public bootstrap returns only widget safe settings, enabled departments and effective availability. Cache config by site and version with ETag; origin validation always occurs before returning tokens. Serve the loader with long cache lifetime under a content hash and a short cached version manifest.
Acceptance criteria
Installing on an approved demo origin renders the widget and creates a real session. An unapproved origin receives no configuration or visitor token. Rotating a site key invalidates the old key after configurable overlap. Refresh during onboarding resumes the saved step. Preview sessions remain excluded from all production counts.
09  Agent roster roles and presence
Required behavior
Invite agents by email, assign departments and roles, enable or suspend access, set per agent chat capacity from 1 to 20. Agent status is online, away or invisible; connected is a separate transport property. Online plus live heartbeat plus available capacity makes an agent eligible. Away keeps existing chats but receives no new offers. Invisible is unavailable and appears offline to visitors while preserving authorized dashboard access. Account suspension revokes all sessions and requeues pending offers; active chats transfer or queue according to policy.
Interface and interaction
Team table columns: name, role, departments, status, active chats, capacity and last seen. Status menu in topbar explains each state; show transport interruption beside status. Agent drawer separates profile, membership, departments and capacity. Dirty edits remain until saved. Last owner cannot be removed or demoted; explain the required ownership transfer.
Implementation contract
Heartbeat every 15 seconds, expire connection after 45; aggregate presence from live connections and declared status. Store durable desired status and ephemeral connections separately. Reservations count toward capacity. Record availability intervals from authoritative server transitions for utilization analytics; do not infer work time from page focus.
Acceptance criteria
Two browser tabs for one agent consume one capacity pool. Losing all agent heartbeats makes new assignment stop within 45 seconds. Closing one tab does not mark the agent offline while another valid connection remains. Suspending the last eligible agent moves new requests to offline or overflow state according to site policy.
10  Departments and queue configuration
Required behavior
A department has name, description, enabled flag, public display label, members, schedule, routing mode, capacity override and overflow policy. Agent memberships may span departments, but total agent capacity is global. Disable a department to stop new chats; existing chats continue. Deleting a department with active chats is rejected; archive instead. A visitor selected department stays explicit unless a routing trigger overrides it before assignment and that override is recorded.
Interface and interaction
Department list shows enabled state, eligible agents, queued chats and schedule state. Detail page tabs: General, Agents, Routing, Hours. Multi select membership search supports keyboard and pending changes. Queue fallback options are leave queued, overflow to another department, or offer offline form. Validate fallback graph for cycles. Widget only exposes enabled public departments and truthful availability.
Implementation contract
Use unique active normalized department names per tenant; store stable IDs independent of labels. Queue settings are versioned and snapshotted on routing decisions. Validate changes server side against active memberships and tenant IDs. Derive public availability from schedule, live eligible capacity and queue acceptance policy, not declared status alone.
Acceptance criteria
A full sales agent who belongs to support cannot receive a fourth chat through support. Archived departments remain named in historical transcripts. A fallback graph A to B to A cannot be saved. A request for a disabled department produces a recoverable widget choice rather than silently discarding the message.
11  Visitor monitoring and live visitor detail
Required behavior
Show live consenting visitor sessions grouped as incoming, currently served, browsing and idle. Display anonymous label or verified identity, current sanitized URL, referrer origin, time on site, current page dwell, country when available, device category, session count, tags, assigned department and chat status. Approximate location is optional and never represented as exact. Presence idle after 60 seconds without interaction; session disconnected after heartbeat expiry and grace. Hide tracking details when consent forbids collection.
Interface and interaction
Desktop visitor table supports search, filters by site, department, country, activity and tag, sort by arrival or queue age, and row selection. List updates preserve selected row and do not jump scroll position. Detail drawer shows visitor summary, page timeline, prior chats and Start chat action. High load mode lists incoming and served chats only, with explicit notice that browsing visitors are omitted.
Implementation contract
Ingest bounded heartbeat, navigation and interaction events; server receipt time governs dwell calculations with clamp rules. Strip URL fragments and sensitive query parameters by default. Never collect DOM content, keystrokes outside widget, passwords or full form values. Persist only needed history; publish coalesced visitor list deltas every second rather than one event per mouse movement.
Acceptance criteria
A visitor navigating an SPA updates page state without creating a new chat. Concurrent tabs appear as one visitor with distinct sessions and a most recently active page marker. Pagination or virtualization keeps 10000 sessions usable. A visitor who withdraws analytics consent disappears from browsing views within 60 seconds while an explicitly requested service chat remains available.
12  Inbox queue and chat workspace
Required behavior
Provide Unassigned, Mine, Department and All permitted chat views. Incoming cards show initial message preview, department, wait duration, visitor name and route reason. Accept reserves and assigns atomically. Active chat layout shows participant names, server ordered transcript, connection status, tags, visitor panel, composer and end action. Multiple chats have accessible tabs with unread counts; inactive chats can notify without stealing focus. Chat status is requested, queued, offered, active, ending or closed; offline submissions are separate records.
Interface and interaction
Queue rows are at least 72 px with 16 px inset, wait timer and explicit Accept. Conversation header is 64 px; transcript padding 20 px, bubble max width 76 percent and 680 px. Composer minimum height 96 px and maximum 240 px. Enter sends by default; Shift Enter inserts newline, with preference to invert. Disable send only for empty input, denied permission or an unresolved terminal state. Offline transport permits an unsent draft with explicit retry, not false delivery.
Implementation contract
Chat commands use expected version, idempotency key and actor scope. Maintain chat owner and participant membership separately. Admission creates the initial message and chat in one transaction. Chat snapshots include last sequence and paginated messages; socket replay begins after that cursor. Queue wait starts at request receipt and does not reset on requeue or transfer.
Acceptance criteria
A visitor on browser A sends a message and an agent on browser B sees persisted text in order. Two agents pressing Accept simultaneously yield one owner and one conflict response. Ending a chat is visible to every participant and prevents further writes. Refresh rehydrates transcript and draft without auto sending the draft.
13  Messaging ordering delivery and reconnect
Required behavior
Text messages support Unicode, line breaks, safe links and emoji; maximum 8000 Unicode code points and 32 KiB encoded payload. No raw HTML rendering. A client creates client_message_id before sending. Server assigns monotonically increasing chat seq in the command transaction. Sent means durable acknowledgment; delivered means a recipient transport acknowledgment; read means the recipient displayed the message in a focused visible conversation. Read receipts are configurable and never inferred from network delivery.
Interface and interaction
Own pending bubble shows Sending; durable success shows Sent; transport confirmation Delivered; permitted read receipt Read. Failure shows Failed with Retry and Copy text. Retry uses the same client ID. A reconnect banner describes recovering messages; preserve transcript and composer. Date separators follow viewer timezone with absolute timestamps available on focus or hover. Long URLs wrap; quoted plain text never becomes executable.
Implementation contract
Enforce UNIQUE(tenant_id, chat_id, client_message_id). ACK contains message_id, seq and committed_at. Use transaction locked next_seq on chat; rollback leaves no visible event. Reconnect requests durable cursor; snapshot on cursor expiry. Gap recovery uses REST, not indefinite buffering. Client applies snapshot before newer events, and deduplicates event IDs as well as message IDs.
Acceptance criteria
Dropping a socket after persistence but before ack and then retrying creates one message. Delivering socket frames out of order renders messages by seq and detects gaps. Browser reload after 100 messages recovers all 100 with no duplicate. A closed chat send receives CHAT_CLOSED and preserves unsent text. An internal note never appears on a visitor socket.
14  Typing unread notifications and attention
Required behavior
Typing is ephemeral, not transcript data. Publish typing start once, refresh at most every 2 seconds, and stop on send, blur or 5 seconds inactivity. Show agent typing to visitor only for public reply mode. Visitor typing preview text is disabled by default; only boolean typing is core. Unread counts advance from per participant last_read_seq; own messages and internal notes invisible to that participant do not inflate visitor unread counts. Notification preference controls audio, desktop alerts and badge behavior.
Interface and interaction
Typing occupies a reserved 20 px row to avoid composer jumps. Unread separator marks first unread visible message. Title badge and chat tabs show count capped visually at 99 plus while accessible label exposes full count. Request desktop permission only after user clicks Enable notifications. Provide sound preview, mute for one hour and per chat mute. Alerts use generic text if privacy mode is enabled.
Implementation contract
Coalesce ephemeral events and drop them before durable message events under backpressure. Use BroadcastChannel for dashboard tab notification leader; elect a replacement on leader expiry. Record read cursor monotonically with max(existing,new). Reject read cursors beyond last visible sequence. Notifications omit full transcript from service worker cache and operating system previews unless explicitly enabled.
Acceptance criteria
A visitor never sees agent private note typing. Switching away keeps unread until the chat is visible and focused. A stale typing event disappears after 5 seconds even if stop is lost. Muting sound does not hide the visual incoming queue. Notifications are not duplicated by two tabs for the same agent.
15  Transfers collaboration and internal notes
Required behavior
Owner can transfer to an eligible agent or department, invite a second agent, leave a collaboration, and add private notes. A direct transfer creates a 30 second offer; current owner keeps responsibility until acceptance. Decline or expiry leaves ownership unchanged and records reason. Department transfer closes pending offers and requeues with original request time and a transfer marker; release capacity only when ownership is relinquished transactionally. Supervisors may force transfer with reason; no silent ownership overwrite.
Interface and interaction
Transfer dialog shows eligible agent load, department availability and optional private handoff note. Confirm button identifies destination. Chat header shows primary owner and collaborators. Reply versus Note switch is persistent and clearly labeled; note composer uses amber tint and a Private to team label. Switching mode preserves separate drafts. An agent leaving the last active ownership path must transfer or end the chat.
Implementation contract
Persist participant role, joined_at, left_at and visibility. Offers have durable state and expiry. Transfer action, capacity counters and outbox events commit together. Notes are messages with visibility=internal and are filtered at query, event and export layers. Record previous and next owner in assignment history for workload attribution.
Acceptance criteria
A transfer to a now full agent fails atomically while current owner remains. An invited collaborator consumes configurable collaboration capacity, default one slot, and cannot accidentally become primary owner. Private notes appear in agent history but never visitor transcript export. Concurrent end and transfer produce one terminal consistent outcome.
16  Chat ending ratings and post chat experience
Required behavior
Visitor or agent may end a chat. Agent end requires confirmation if the visitor is still connected; visitor end presents clear finality. Transport disconnect alone does not immediately end chat: hold for 5 minutes reconnection grace, configurable from 1 to 30. Agent can close abandoned chat sooner with a reason. Terminal close writes one closed_at, close_reason and closed_by. Ratings are good or bad with optional comment up to 2000 characters, available during active chat or for 24 hours after close through a scoped grant.
Interface and interaction
Closed transcript remains readable with a Chat ended separator and New chat action. Rating controls use labeled thumbs with selected state and accessible pressed attribute. Changing rating updates the same record within the allowed window and shows saved state. Email transcript request appears after close; visitor enters or confirms email. Do not force a rating before allowing exit.
Implementation contract
Use chat version lock to finalize. Stop pending routing and timers, release reservations and capacity, append close event, and enqueue analytics plus optional ticket export. Keep rating history auditable but report latest rating at metric cutoff. Redact rating text during erasure. Closing due to inactivity is attributed separately from an agent explicitly resolving the conversation.
Acceptance criteria
Two end commands produce one close transition and idempotent acknowledgment. A visitor returning within grace resumes the same chat; returning after close creates a new chat. A forged rating token for another chat is rejected. Repeated rating changes do not multiply CSAT denominator. Ended chats remain searchable subject to retention.
17  History search tags and visitor records
Required behavior
History lists closed and active chats with date, visitor, agents, department, duration, tags and rating. Search permitted public message text and private notes only for roles allowed to read notes; filter by site, agent, department, rating, tag, status and inclusive date input converted to half open UTC bounds. Visitor profile has verified and unverified identity fields distinguished, editable name, contact email, tags, custom fields and previous chats. Merge requires admin review and verified identity proof; never merge solely by matching email text.
Interface and interaction
History uses 48 px rows, 50 per page and cursor pagination. Filter chips can be removed individually and saved. Search text is debounced 300 ms; result snippets highlight matched text safely. Detail opens as a route with transcript and metadata tabs. Tag picker offers existing tags before new creation, with normalized lower case slug max 64 and display label max 80. Empty search shows Clear filters.
Implementation contract
PostgreSQL full text index uses explicit text search config; filter tenant and permission scope before ranking. Use stable cursor(created_at,id), cap search result window and query length 256. Keep tags relational rather than an unbounded JSON string array. Custom fields have schema, type, validation and public visibility flag; deny arbitrary nested object injection.
Acceptance criteria
Search yields no other tenant or unauthorized department data, including snippets and count. Deleting a tag removes future association while retaining audited historical snapshot when policy allows. A 23 hour daylight saving day filters correctly. Changing a visitor display name does not rewrite historical sender snapshots.
18  Canned replies and shortcut expansion
Required behavior
Provide tenant shared, department scoped and personal canned replies. A reply has unique scope plus shortcut slug, title, body, tags and enabled state. Slash shortcut inserts text into composer but never sends automatically. Supported placeholders: visitor.name, agent.display_name, department.name, site.name. Missing values use a defined fallback or highlight unresolved token and block send until resolved. No executable template expressions. Sharing and editing require permissions; agents may manage personal replies.
Interface and interaction
Composer slash opens searchable suggestion menu with shortcut, title and body preview; arrows navigate, Enter inserts, Escape dismisses. Shortcut manager includes list, preview, create, duplicate, archive, bulk import and CSV export. Body editor is plain text, max 8000 code points. Preview allows sample visitor values and clearly shows unresolved variables. Preserve cursor position on insertion.

25  Visitor identity and session semantics
Three distinct objects
Visitor is a tenant scoped durable identity. Session is one site browser browsing episode with a unique session ID. Connection is one transport on one tab or device. A visitor may have many sessions and connections, and a chat may survive a connection loss. Anonymous visitor IDs are generated by cryptographic random source and stored first party by the host loader when allowed. Session ends after 30 minutes inactivity, while an active chat may reconnect through its scoped resume grant. Define started_at, last_seen_at and ended_at using server time.
Verified identification
SDK identify with name or email marks fields unverified and only prepopulates forms. Verified identity requires a short lived JWT generated by the customer backend with tenant configured secret or asymmetric key. Claims: iss customer integration ID, aud talkivio visitor, tenant_id, site_id or allowed site set, sub stable customer ID, iat, exp no more than 5 minutes, jti, optional name and email. Bind claim to site authorization and prevent identity switching during active chat without explicit reset. Matching verified external ID can join browser identities through audited association; matching email alone cannot.
Storage and logout
Keep anonymous identity under talkivio:<siteKey>:visitor with version and expiry; default 180 days if consent permits. Session ID uses sessionStorage with coordinated duplicate tab behavior; each tab has its own connection ID. No cookies that assume third party storage access. Host app logout invokes resetIdentity: close transport, clear personalized caches, replace anonymous ID and prevent prior transcript display to next user. Do not erase server records merely because a browser logs out.
Acceptance criteria
Two users sharing a device see no prior user transcript after reset. A forged identify email cannot access verified customer history. A valid external ID on a second browser can see only chats permitted by that authenticated visitor policy. Disabled localStorage and private browsing still support an in memory service chat with documented inability to resume after full reload. Visitor identity associations never cross tenants.
26  Cross domain tracking and consent
Cross origin limitations
Different unrelated domains cannot safely share first party localStorage or a universal cookie. Implement cross domain continuity through the same verified external customer ID on each origin, or an explicit consented one time handoff issued by the customer backend. Do not claim anonymous identity magically persists across unrelated domains, use fingerprinting, or depend on third party cookies. Related subdomains may use an explicitly configured parent domain cookie only if the tenant proves control and accepts its wider access exposure.
Handoff protocol
A server generated handoff has source site, destination site and exact origin, visitor association, nonce, expiry 60 seconds and purpose resume. Exchange once through POST, require destination origin, then bind a new visitor session token. Prefer backend exchange over URL tokens. If a redirect carries a short code, immediately redeem, replace browser URL to remove it and set no referrer leakage; the code contains no PII. Do not transfer active chat ownership to an untrusted domain. Recheck allowed origin and consent at redemption.
Consent states
Consent is unknown, granted, denied or withdrawn with separate service and analytics purposes. Prior to analytics grant, loader must not create persistent browsing identity, emit navigation or referrer events, or display behavior based invitations. Explicit visitor request may establish a short lived service session needed for the requested chat. Store consent policy version, timestamp, source and purpose. Withdrawal stops optional events immediately, clears optional storage and schedules deletion according to policy; it does not falsely report erasure complete before durable workers finish.
Event collection
SDK navigation accepts URL and title; sanitize server side and default to path plus origin, query allowlist empty, fragments removed, title max 200. Track visibility, page load, safe interaction signal and heartbeat without scraping host page text. Aggregate dwell across visible tabs without double counting overlapping intervals. Handle bfcache pageshow, SPA history changes, offline networks and pagehide best effort. Tests cover Safari storage partitioning, incognito, blocked third party storage and consent withdrawal mid chat.

30  Routing eligibility and deterministic selection
Eligibility order
Inside routing transaction: reject terminal chat; check tenant and site acceptance; apply selected department and validated pre assignment trigger override; resolve schedule and emergency closure; filter enabled live online agents with department membership; subtract active ownership, capacity counted collaborations and unexpired reservations from global capacity; exclude agents who declined that request during 60 second cooldown. Skills matching is optional and occurs only after mandatory eligibility. No eligible agent leaves request queued or invokes configured overflow; never assigns an unavailable agent to satisfy a demo.
Modes and priorities
Core modes: manual pickup; broadcast offer where all eligible agents see the request but one wins acceptance; assigned offer where one candidate is chosen. Assigned selection defaults least normalized load (active plus reservations divided by capacity), then earliest last_assignment_at, then agent UUID ascending. Round robin optional uses durable department cursor and skips ineligible agents. Request priority is server trusted integer 0 to 100, default 50; order by priority descending then requested_at ascending then chat UUID. Client tags do not raise priority without trusted rule.
Fairness and reservations
Use durable assignment offers as reservations. Offer duration 30 seconds; agent acceptance transitions offer and chat atomically while counting capacity. Decline or timeout releases reservation and retries next candidate. Apply aging: effective priority=min(100,base+floor(wait_seconds/60)), but freeze request ordering within a routing cycle for determinism. Cross department capacity checks lock membership capacity state in consistent UUID order. Broadcast does not reserve every agent; winner acquisition must test capacity at accept time.
Acceptance criteria
One queued chat has at most one primary owner and assigned mode at most one live single target offer. Two simultaneous requests cannot exceed capacity. A worker crash releases reservations only after durable expiry. Equal load tie breaking is reproducible. Test 100 requests with 10 agents at capacity 3, random accepts/declines, two routing workers and agent disconnects; assert no lost queue rows, double ownership or negative capacity.
31  Routing transaction and overflow pseudocode
Contract example
route(chatId):
  begin tenant transaction
  chat = SELECT chat FOR UPDATE
  if chat.state not in {queued, offered}: return currentState
  expire old offers and audit expirations
  config = load published routing revision
  candidates = eligibleAgents(chat, config)
  if candidates empty: applyQueuePolicy(chat); commit; return
  agent = deterministicSelect(candidates)
  lock agent capacity row; recompute eligibility and free slots
  if no slot: rollback and bounded retry with jitter
  insert offer with expires_at = databaseNow + 30 seconds
  update chat state offered, version = version + 1
  append assignment.offered outbox event
  commit
accept(offerId, expectedVersion, key):
  begin; verify membership and command idempotency
  lock chat then capacity rows in documented consistent order
  verify offer pending, unexpired and assigned to actor
  verify current eligibility and global capacity
  expire competing offers; add owner participant
  set owner, state active, first_assigned_at if absent
  append assignment history and outbox events; commit
Overflow behavior
Queue policy has max waiting count default 1000 per department and max wait default 300 seconds; both configurable. Admission over count does not discard request: return capacity decision and offer offline submission before creating chat, or create a clearly overflowed request if tenant policy specifies. At max wait, notify visitor with options continue waiting or offline form; default no silent closure. Department fallback applies once per configured edge and records visited departments to prevent loops. Overflow does not reset requested_at or increase metrics denominator twice.
Revalidation and contention
Use lock ordering consistently across route, accept, transfer and close to prevent deadlocks. SELECT FOR UPDATE SKIP LOCKED is suitable for queue worker claims, not a substitute for chat and capacity integrity. Retry serialization or deadlock failures at most 3 times, retain idempotency key and return retryable conflict after exhaustion. Agents transitioning away cause unaccepted offers to expire or withdraw; active ownership remains unless separate transfer policy fires.
Verification
Inject a scheduling barrier between capacity read and reservation write to test races. Expired offers must never be accepted even if client UI is stale. Kill worker mid transaction and prove rollback; kill after commit and prove outbox recovery. Preserve every route decision with candidate count, chosen reason, configuration revision and causation ID for supervisor explanations.
32  Trigger DSL conditions and action grammar
Versioned language
Implement declarative JSON DSL version 1, never eval or arbitrary JavaScript. Trigger contains id, name, enabled, priority integer 0 to 1000, event, all conditions, any conditions, actions, stopProcessing, cooldownSeconds and version. Events: visitor.session.started, visitor.page.changed, visitor.timer.elapsed, chat.requested, message.created where actor=visitor, chat.queued, chat.closed and offline.submitted. An empty all group is true; empty any group is ignored. Condition evaluation requires every all and at least one any when any is nonempty.
Conditions
Fields allowlist: site.id, department.id, visitor.verified, visitor.country, visitor.tags, visitor.returning, page.path, referrer.origin, session.time_on_site_seconds, page.visible_dwell_seconds, chat.wait_seconds, chat.status, message.text, schedule.is_open, eligible_agent_count and trusted custom fields. Operators are eq, neq, contains, starts_with, ends_with, in, not_in, gt, gte, lt, lte, exists and missing. Strings max 2000; numeric operands finite. Missing field fails normal operators, including neq; use missing explicitly. Country only available when permitted. Regex is optional with RE2 compatible bounded pattern engine, never unbounded native regex.
Actions
Allow set_department, set_priority, add_tag, remove_tag, send_public_message, display_invitation, set_visitor_field, notify_department, create_webhook_job and block_admission. Validate action permissions, field visibility and target IDs on publish. set_department and set_priority only before assignment. A public message action has declared attribution automated team and plain text. Notifications do not consume chat capacity. No direct owner manipulation, secret access, arbitrary HTTP target, filesystem operation or code execution.
Contract example
{"dsl_version":1,"event":"chat.requested","priority":100,
 "all":[{"field":"page.path","op":"starts_with","value":"/pricing"},
        {"field":"schedule.is_open","op":"eq","value":true}],
 "any":[],"actions":[{"type":"set_department","department_id":"<sales-id>"},
 {"type":"add_tag","tag":"pricing"}],"stop_processing":true,

Validation
Editor and API share grammar validation; reject unknown keys, invalid enum values, illegal operator types, cross tenant references and action arrays over 20. Max 50 total conditions, nesting only one group depth in v1. Reject conflicting writes within one trigger unless explicit action order resolves them. Persist full validated revision for deterministic replay.
33  Trigger precedence execution and simulation
Evaluation order
Triggers evaluate highest priority first, then creation time ascending, then ID. Each event gets one immutable snapshot of visitor, chat, schedule, site and authoritative time. Matching does not change for later triggers due to earlier actions. Collect actions from matches until stopProcessing on a matched trigger. Conflicting set_department or set_priority uses first winning action. add/remove tag follows collected action order. Terminal block_admission wins over admission and suppresses later visitor messages; configured audit trace explains suppression. Do not let a lower priority trigger silently reroute a previously won department.
Idempotency and recursion
Create trigger_run unique on tenant,event_id,trigger_id,revision. Action effect unique on run_id,action_index. Execute durable effects in a transaction or outbox job with effect key; retry cannot send a duplicate greeting. System generated messages do not emit the visitor message event. Propagated causation_id plus depth limit 3 prevents cycles; repeated ancestor trigger action is rejected. Cooldown is scoped to trigger and visitor session by default; campaign dismissal cap is an additional guard. Timer events are durable scheduled jobs, not browser setTimeout authority.
Interface
Trigger builder lists enabled state, event, priority, last matched and error count. Condition rows have field, operator and type appropriate value editor; all and any visually labeled. Reorder through accessible Move up and Move down buttons as well as drag. Simulator accepts safe sample visitor and chat data, returns matched triggers, condition truth values, collected effects and suppressed actions. Publish requires valid draft and version check. Revision history can restore a previous version as a new revision.
Acceptance criteria
Pricing and generic greetings matching the same event produce configured single invitation, not two popups. Retry same event produces same effect once. Missing country does not satisfy neq country. A trigger trying to reroute an active chat is rejected or records action skipped with reason. Simulator and production engine share the exact interpreter. Test stop processing, priority ties, cooldown expiry, recursive events, disabled revision and concurrent publish.
34  Database conventions constraints and migration policy
Scalar types and defaults
Use UUID generated by database or validated server generator, timestamptz for instants, text for bounded strings enforced with CHECK, bigint for sequence and byte counts, integer for small counts and priorities, boolean for flags, numeric(12,2) for money only when billing enabled, inet for protected network data if retained, and jsonb for validated configuration snapshots. For tenant owned entities add UNIQUE(tenant_id,id); children reference (tenant_id,parent_id) to parent(tenant_id,id). Table entries below list business fields in addition to these common fields. Composite junction primary keys include tenant_id and both referenced IDs. Optional timestamps and text are marked ?. Enumerated text has CHECK with values listed in the domain contracts. No unconstrained status string. Use soft archive for configuration referenced by history, hard erase for personal payload under retention. Audit tombstones must not retain erased PII.

Every tenant scoped list index begins tenant_id and includes sort tie breaker id. Add indexes for FK lookups used by deletes and joins. Avoid global unique emails in visitor records; membership email belongs to global user account identity, not visitor identity. Migrations
SQL migrations are ordered, immutable after release, transactional when possible and tested from empty database and prior release snapshot. Capture schema version at startup, reject incompatible deployment, and document data rollback rather than pretending all migrations are reversible.

40  REST conventions and shared resource shapes
Base paths and authentication
Agent API is /api/v1 with active tenant derived from session or tenant scoped integration token. Public widget API is /widget/v1 with siteKey bootstrap and subsequent visitor capability. Admin must not reuse widget credentials. REST JSON uses snake_case; SDK wraps camelCase deliberately. UUID path IDs validated before lookup. OpenAPI 3.1 is generated from runtime schemas; reject unknown input fields. TLS required; JSON content type mandatory for JSON writes. CORS permits exact approved origins and never wildcard with credentials.
Responses and errors
Single success: {data:Resource,meta:{request_id}}. List: {data:Resource[],page:{next_cursor,has_more},meta:{request_id}}. Error: {error:{code,message,field_errors?,retryable},meta:{request_id}}. Default page size50, maximum100. Opaque cursor encodes sort keys and scope, signed or validated; reject cursor for another filter. GET200, create201 with Location, accepted async202, no body204, invalid schema422, unauthenticated401, permitted known scope but forbidden action403, hidden object404, version/idempotency/state conflict409, rate limit 429 with Retry-After. Sensitive object existence is always404.
Shared resources
Chat: id,site_id,visitor_id,department_id,status,owner_membership_id,requested_at,first_assigned_at,closed_at,priority,version,last_seq. Message: id,chat_id,seq,client_message_id,sender:{type,id,display_name},visibility,type,body,attachments[],sent_at. Visitor: id,display_name,verified,allowed_contact_fields,tags[],custom_fields,first_seen_at,last_seen_at. Offer: id,chat_id,mode,target_membership_id,expires_at,status,version. Job: id,kind,state,progress?,created_at,completed_at?,error_code?,expires_at?. Timestamp fields RFC3339 UTC. Never return internal fields on public shapes.
Writes and limits
All create and command POSTs accept Idempotency-Key UUID or random 16 to128 character key. Hash request canonically and scope by principal, tenant and route. Same key different payload returns409; identical retry returns original status and resource for 24 hours. PATCH and destructive configuration commands use If-Match entity version; missing precondition428 and stale409. Message unique client ID is permanent beyond command cache expiry. Request body limit 256 KiB except streamed uploads. Numeric limits, enum values, array bounds and error examples exist in OpenAPI.

47  WebSocket handshake envelope and replay
Handshake
Gateway path /realtime/v1. Mint single use 30 second ticket through authenticated REST; send as first auth frame over TLS within 5 seconds. Validate browser Origin against dashboard or site allowlist before accepting. Do not place long lived bearer credentials in URL, logs or subprotocol text. Ticket binds tenant, principal, site, session and scopes. Server auth.ok includes connection_id, heartbeat_interval_ms=15000, capability_expiry, and resumable scopes. Refresh capability before expiry or close with explicit authentication reason.
Envelope
Durable server frame: {v:1,event_id:uuid,type:string,tenant_id:uuid,scope:{kind:chat|queue|visitor|config,id:uuid},cursor:string,occurred_at:RFC3339,aggregate_version:int,causation_id:uuid,payload:object}. Client command: {v:1,command_id:uuid,type:string,scope:{kind,id},expected_version?:int,payload:object}. Server command.ack: {command_id,result:{resource_id,seq?,version?},committed_at}; command.error: {command_id,code,message,retryable}. Tenant field is server supplied and is not accepted as client authority. Ephemeral frames contain expires_at and no replay cursor.
Subscription and recovery
Client sends subscribe {scopes,last_cursor?}; server validates every scope and returns subscription.ok with snapshot_cursor. Durable cursor is opaque and monotonic within subscribed stream; do not assume Redis PubSub persistence. Store event replay for24 hours by default and use safe retention consistent with erasure. On cursor expired respond snapshot.required; client fetches snapshot and resubscribes after its cursor using a race safe barrier. Resume buffers live events until replay is complete. Visibility filtering must not reveal private note content; public stream cursors are opaque and public visible seq gaps are valid.
Reliability and limits
Delivery is at least once; clients deduplicate event_id and aggregate version. Ping/pong every15 seconds and close after 45 seconds missed heartbeat. Max frame64 KiB, max client commands10persecond sustained with burst20, typing at most one per2 seconds. Outbound buffer maximum1 MiB or1000events; drop ephemeral first, then close slow client with resumable overload reason. Use jittered reconnect 0.5,1,2,4,8 seconds capped30. REST writes remain fallback authority; an SDK must not send the same command concurrently through REST and WS without the same idempotency identity.

50  Analytics definitions and attribution
Chat population
Report requested chats by requested_at in the selected half open UTC interval; exclude preview chats. Served chat is one with at least one human agent public message. Assigned is one with first_assigned_at, which is not equivalent to served. Missed is closed without human public response after an admitted request, excluding visitor cancellation within 10 seconds when configured and separately disclosed. Abandoned is visitor ended or grace expired before first assignment; missed and abandoned may overlap, so never add them as mutually exclusive without explicit partition definition. Offline submissions are separate population.
Durations and rates
Wait to assignment = first_assigned_at minus requested_at. First response time = first human agent public message timestamp minus requested_at, including queue time; service response time subtracts first_assigned_at separately. Chat duration = closed_at minus requested_at for closed chats; handling duration per owner interval excludes queue. Response time between turns starts at first visitor message in a contiguous visitor burst and ends at next human public reply. Automated greetings and private notes never stop response timer. Missing reply yields null duration, not zero. Use count, median, p90 and p95 with explicit sample count.
Quality and utilization
CSAT = latest good ratings divided by latest good plus bad ratings for chats in cohort, expressed percentage; unrated excluded and response rate separately equals rated divided by served. Agent utilization = capacity slot seconds occupied divided by available capacity slot seconds during online eligible intervals; cap only for reporting correction and flag invariant violations. Multiple chats may overlap, so wall clock summed handling time cannot be divided by wall clock availability without accounting capacity. Transfers attribute replies to actual author and ownership duration to interval owner; distinct chats handled per agent can exceed unique tenant chats.
Cohorts and freshness
Default cohorts group by requested_at, display timezone chosen by user with timezone label. Daily bucket boundaries derive from IANA timezone and may span23 or 25 hours. Department acquisition dimension snapshots department at initial admission; current department is separate filter. Include requested, assigned, served, missed, abandoned, ratings, invitation displays/accepts and offline counts. Late rating and transfer updates revise facts idempotently. Report updated_at and source watermark; no event yet means zero count, unavailable aggregator means unavailable, percentile with no samples means null.

52  Security threat model and controls
Threat inventory
Document attacker classes: anonymous spammer, malicious visitor, malicious agent, compromised tenant admin, stolen session, hostile embedding origin, compromised webhook destination and infrastructure operator. Assets: transcripts, visitor identity, authentication material, integration secrets, attachments, tenant configuration and billing. Map entry points and trust boundaries for browser loader, iframe, REST, sockets, database, queue, object store, email and provider callbacks. For each threat list control, test and residual risk.
Application controls
Validate schemas and permissions on every command including sockets. Escape text output, sanitize permitted links to http/https/mailto, reject javascript/data links, and use noopener for external links. Parameterize SQL; never interpolate sort fields without allowlist. CSRF for cookie writes, exact Origin for websocket, CORS allowlist, secure cookie flags and content security policy. Limit requests and tenant quotas before expensive work. Secrets stored encrypted with key version, resolved server side and redacted from logs. Rotate signing keys with a bounded overlap and reject retired keys.
Infrastructure controls
TLS1.2orhigher externally; service credentials least privilege; production database and object store private network. Nonroot containers, read only root filesystem where feasible, dropped capabilities, resource limits and separate service accounts. Dependency scanning, secret scanning, SBOM and signed build provenance in CI. Restrict administrative operational endpoints. Cloud credentials use workload identity when available rather than static keys in images. No production secrets in seed fixtures, build args or source map uploads.
Security acceptance
Run integration tests for IDOR, cross tenant access, CSRF, session fixation, reset replay, malicious HTML message, dangerous URL, SQL injection filters, socket origin spoof, malformed frames, oversized payloads, SSRF webhook, malicious file and privilege escalation. Perform a documented manual review of authorization paths and exports; automated scanner passing is insufficient. No known exploitable critical/high finding can remain without owner accepted release exception and compensating controls. Produce security.md and incident response playbook.
53  Privacy GDPR tooling and retention
Privacy implementation
Implement data minimization, per purpose consent records, configurable retention, access export, erasure, auditability, processor documentation support and tenant data export. Provide privacy settings for browsing collection, IP retention, location enrichment, transcripts, page events, attachments and exports. Privacy defaults favor minimum data. Do not claim legal certification from implemented controls. Deployment owner must configure lawful basis, notices, processor agreements, regional hosting and request handling deadlines for its jurisdiction.
Access and erasure workflows
A verified access request queues a full subject export including identities, sessions, chats, ratings, custom fields and relevant consent records, without other visitors or private staff notes unless policy requires authorized review. Erasure enumerates database payloads, FTS vectors, object originals and thumbnails, cached snapshots, pending jobs, export files, integration delivery payloads and analytics identifiers. Mark request running, block new identity linkage, redact public transcript personal text according to tenant policy, invalidate download grants and record safe counts. Backups and downstream systems
Immutable backups cannot usually edit individual records. Maintain erasure tombstone ledger outside restored backup scope with pseudonymous identifiers and replay erasures before a restored environment accepts traffic. Expire backups according to policy and prevent erased exports from restoration. Downstream connectors receive deletion events and track confirmation; do not pretend a third party is erased if it only accepted a request. Legal holds are privileged, reasoned, scoped and visible in privacy report, with allowed access restriction.
Acceptance criteria
Seed a distinctive visitor string across message text, search, attachments, exports, jobs and logs, then erase and verify it is inaccessible in all active stores and scoped caches. Another visitor in the same chat relation is not accidentally erased. Restore a pre erasure backup and prove tombstone replay removes the string before readiness. Retention jobs respect holds and process bounded batches; dry run reports targets before destructive production execution. Record request verification evidence with separate short retention.

Outbound event contract
Support chat.requested, chat.started, chat.closed, rating.updated, offline.submitted and privacy.erased. Body {id,type,version,occurred_at,tenant_id,data}; id is stable event ID across retries. Headers X-Talkivio-Event-Id, X-Talkivio-Timestamp and X-Talkivio-Signature v1=<hex HMAC SHA256(secret,timestamp+"."+raw_body)>. Receiver verifies raw bytes and timestamp within 5 minutes, deduplicates event ID and returns2xx. Delivery guarantee at least once; no assumption of global ordering.
Retry and SSRF
Attempts at approximately0,10 seconds,1minute,5 minutes,30 minutes,2 hours,8 hours,24 hours with jitter then dead letter. Retry408,429 and 5xx; most other4xx require correction. Respect bounded Retry-After. HTTP timeout10 seconds, response body cap64 KiB; no redirects by default. Resolve URL and block loopback, private, link local, cloud metadata and nonHTTP schemes at save and at every dispatch to resist DNS rebinding. Egress proxy allowlist recommended. Endpoint test uses safe sample body.
Integration credentials
Tenant scoped API tokens have allowlisted scopes such as chats:read, chats:write, visitors:write, analytics:read and webhooks:manage. Show secret once, store hash for incoming API keys; outbound secrets encrypted. Token expires by default 90 days and supports revoke, last used timestamp and rotation. Token cannot exceed creator permissions. Provider adapters implement authenticate, healthCheck, createTicket, updateTicket, exportChat and eraseSubject as appropriate, with retry classification and external idempotency mapping.
Acceptance criteria
Local webhook receiver verifies signatures, simulates429 and 500, deduplicates retries and records final success. URL to127.0.0.1 or169.254.169.254 is rejected in production configuration, with an explicit test environment exception for local receiver only. A token revoked while socket active loses access within 60 seconds. Contract tests exercise every adapter success, retry, permanent failure, invalid credentials and subject deletion without making false external success claims.

Reject additional fields and validate all referenced objects in same tenant.
Chat transition table
requested to queued after admitted request persistence; queued to offered when assigned offer created; queued/offered to active only on valid accept transaction; offered to queued on withdrawal/expiry when no active owner; active to active on direct owner transfer or collaborator changes; active to queued on explicit department handoff relinquishing ownership; queued/offered/active to ending when an authorized close command obtains lock, then closed in same committed operation; closed is terminal. ending need not be externally observable if closure is one transaction. Queue to offline submission conversion closes request with converted_offline reason in same transaction as submission. Each transition defines audit/event, capacity effect and expected version.
Other transition guards
File clean and rejected are terminal scan decisions except privileged rescan; uploaded cannot skip scanning. Offer pending can become accepted,declined,expired,withdrawn only; decision terminal. Export queued to running to ready or failed; ready to expired/erased revokes grant. Privacy pending_verification to queued only after proof; queued to running to completed or failed, with explicit resume on safe retry. Trigger draft revision to published immutable; restore creates another draft. Illegal transitions 409 with current safe state, not500.
Schema gaps and referential integrity
Do not use polymorphic sender_id as sole unconstrained identity relationship. Implement messages sender_membership_id uuid nullable and sender_visitor_id uuid nullable with composite foreign keys and CHECK ensuring agent has membership only, visitor has visitor only, system has neither; sender display snapshot is safe and redacted on erasure. Integration mappings table includes provider,source_type,source_id,external_id,last_synced_revision,status, with UNIQUE(tenant_id,provider,source_type,source_id) and provider scoped external uniqueness. Subject tombstone table includes tenant,protected subject hashes,erasure_request_id,erased_at and ledger checkpoint; keep outside restorable active database scope as documented.

Allowlisted client commands

REST fallback coverage
Add POST /widget/v1/invitations/{id}/displayed {} for display acknowledgment; PUT /widget/v1/chats/{id}/read-cursor {last_read_seq}; GET /widget/v1/uploads/{id} for scan state; GET /widget/v1/attachments/{id}/download for scoped clean grant; GET /widget/v1/exports/{id} and GET /widget/v1/exports/{id}/download for own export job. Sequence and visibility
Public users see message seq values that may skip private note sequence numbers. Gaps in public seq must not trigger endless missing-message fetch: REST page response includes through_seq, the aggregate cursor covered, plus visible messages and has_more. Client advances coverage to through_seq even when there are no visible messages in that interval. Agent with full scope uses same rule for redacted rows. Resume uses opaque event stream cursor, not message seq as a substitute. Tests specifically cover a public message, private note and next public message sequence1,2,3 with visitor seeing1 and 3 without leak or infinite retry.
Conflict and reconnection policy
After state conflict refetch authoritative snapshot before enabling stale offer or close action. Retry network ambiguity using same command_id/client_message_id; retry validation only after edits with a new command identity. Outbox replay cannot resurrect a locally redacted body; apply newer aggregate and privacy versions. Clear principal scoped caches on access revocation and tenant switch. A socket reconnect never automatically sends a stored draft unless a previously submitted command is still awaiting acknowledgment, and then only with its original idempotency identity.
